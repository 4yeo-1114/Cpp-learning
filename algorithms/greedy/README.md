## 逐题详解

### 1. 最长递增子序列 (LIS) — `lengthOfLIS.cpp`

**题目**：给定数组，求最长严格递增子序列的长度（子序列不要求连续）。

**贪心思路**：
- 维护数组 `d[]`，`d[len]` 表示当前长度为 `len` 的递增子序列的**最小可能结尾值**
- 遍历每个数 `x`：
  - 若 `x > d[len]` → 拼在末尾，`d[++len] = x`
  - 若 `x ≤ d[len]` → 二分找到第一个 `< x` 的位置 `pos`，替换 `d[pos+1] = x`（**换血**：把结尾变小，给后面更大的数留空间）
- 时间复杂度：**O(n log n)**

**模板骨架**：
```cpp
vector<int> d(n+1);
int len = 1;
d[len] = nums[0];
for (int i = 1; i < n; i++) {
    if (nums[i] > d[len])
        d[++len] = nums[i];
    else {
        // 二分：找最后一个 < nums[i] 的位置
        int l = 1, r = len, pos = 0;
        while (l <= r) {
            int mid = l + (r-l)/2;
            if (d[mid] < nums[i])
                pos = mid, l = mid + 1;
            else
                r = mid - 1;
        }
        d[pos + 1] = nums[i];
    }
}
return len;
```

> **核心思想**：结尾越小，后面越容易接上。贪心地让每个长度的子序列结尾尽可能小。

### 2. 吃糖果 — `eatcandy.cpp`

**题目**：有 n 盒糖果排成一排，相邻两盒糖果数之和不能超过 x。每次可以从任意一盒中"吃"掉一颗糖果。问最少吃多少颗。

**贪心思路**：
- 从左到右遍历，检查 `a[i] + a[i-1] > x`
- 若超标：**削减右边的 `a[i]`**，因为 `a[i]` 还会影响 `a[i+1]`（而 `a[i-1]` 只影响当前这一对）
- 时间复杂度：**O(n)**

**模板骨架**：
```cpp
for (int i = 1; i <= n; i++) {
    cin >> a[i];
    if (a[i] + a[i-1] > x) {
        long long diff = (a[i] + a[i-1]) - x;
        ans += diff;
        a[i] -= diff;              // 优先减右边
    }
}
```

> **核心思想**：局部最优 = 全局最优。右边的元素影响面更广，所以优先削减它。

### 3. 删数字 — `deletenums.cpp`

**题目**：给定一个长数字串，删除 k 个数字，使剩下的数字组成的数**最小**（可以有前导零，但要处理全零的情况）。

**贪心思路**：
- 最终保留 `rest = n - k` 位
- 从左到右，每次在还能删除的范围内（当前起点到 `起点+k`），选**最小的数字**作为下一位结果
- 选完后，起点移到选中位置+1，`k` 减去跳过的数字数
- 时间复杂度：**O(n²)**（可优化到 O(n) 用单调栈）

**模板骨架**：
```cpp
int rest = n - k, t = 1;   // t 是当前搜索起点
while (cnt < rest) {
    int minp = t;
    for (int i = t; i <= t + k; i++)   // 在可删范围内找最小的数字
        if (a[i] < a[minp]) minp = i;
    if (a[minp] != 0) flag = 1;        // 非零了才开始输出（处理前导零）
    if (flag) cout << a[minp];
    k -= minp - t;                      // 消耗掉跳过的数字
    t = minp + 1;
    cnt++;
}
```

> **核心思想**：高位越小，整体数越小。每次在允许的范围内选最小的数当高位。

### 4. 合并果子 — `mergeapples.cpp`  ⭐ 经典哈夫曼

**题目**：有 n 堆果子，每次合并任意两堆，代价 = 两堆重量之和。问把所有堆合并成一堆的最小总代价。

**贪心思路**：
- 每次取重量**最小的两堆**合并，新堆放回去
- 重复直到只剩一堆
- 这本质是**哈夫曼树的构建过程**

**解法一：小根堆 `priority_queue`（通用）**
```cpp
priority_queue<int, vector<int>, greater<int>> min_heap;  // 小根堆
// 全部 push 进去
while (min_heap.size() > 1) {
    int a = min_heap.top(); min_heap.pop();
    int b = min_heap.top(); min_heap.pop();
    total += a + b;
    min_heap.push(a + b);
}
```
- 时间复杂度：**O(n log n)**

**解法二：桶排序 + 双队列（数据范围小时更优）**
```cpp
// 因为每次合并出的新堆重量单调不减 → 用两个有序队列归并
// 队列1：原始果子（桶排序后有序）
// 队列2：合并产生的新堆
// 每次从两个队头取最小的两个
```
- 时间复杂度：**O(n + W)**，W 为值域大小

> **核心思想**：小的先合并 → 它们不会在后续反复被加（被加的次数少），总代价最小。

### 5. 任务调度 — `task.cpp`  ⭐ 反悔贪心

**题目**：n 个任务，每个任务有截止时间 `d` 和收益 `p`。每个时间单位只能做一个任务。问最大总收益。

**贪心思路（反悔贪心）**：
1. 按**截止时间升序**排序
2. 遍历每个任务，用小根堆维护"已接取任务的收益"
   - 若当前任务数 `< d`：直接接取（时间还够）
   - 否则：若当前收益 > 堆顶（已接取中最差的），**反悔**——踢掉最差的，换入当前任务
3. 时间复杂度：**O(n log n)**

**模板骨架**：
```cpp
sort(tasks.begin(), tasks.end(), [](auto& a, auto& b) { return a.d < b.d; });

priority_queue<long long, vector<long long>, greater<long long>> pq; // 小根堆存收益
long long ans = 0;

for (auto& t : tasks) {
    if (t.d > pq.size()) {               // 时间容量够 → 直接接
        ans += t.p;
        pq.push(t.p);
    } else if (pq.top() < t.p) {         // 反悔：换掉最差的
        ans += t.p - pq.top();           // 补差价
        pq.pop();
        pq.push(t.p);
    }
}
```

> **核心思想**：先贪心接纳，发现更优时**反悔**换掉之前的差选择。堆里始终维护"当前最优的任务集合"。

## 通用模板总结

### 模板 A：排序 + 遍历 + 堆（最高频）

适用于：任务调度、合并果子、区间选择等

```
1. sort(按某关键字排序)
2. priority_queue<..., greater<...>> pq;   // 小根堆
3. for (auto& item : items) {
       if (满足条件) 直接加入;
       else if (当前比历史最差好) 反悔替换;
   }
```

题目：task.cpp, mergeapples.cpp

### 模板 B：维护单调最优值

适用于：LIS、单调栈贪心

```
1. 遍历每个元素
2. if (满足扩展条件) 扩展;
   else 二分找到位置，替换（优化潜在空间）
```

题目：lengthOfLIS.cpp

### 模板 C：局部决策 → 全局最优

适用于：相邻约束、一步贪心

```
1. 从左到右遍历
2. 每一步做当前最优的局部决策
3. 因为决策只影响后续，不影响前面 → 局部最优 = 全局最优
```

题目：eatcandy.cpp, deletenums.cpp

## 通用解题思路（做题时按此顺序思考）

| 步骤 | 问题 |
|---|---|
| ① | **排序依据**：按什么关键字排序？截止时间？价值？起点？ |
| ② | **贪心策略**：每一步选什么？选最大的？选最小的？选最早的？ |
| ③ | **正确性检验**：局部最优是否导致全局最优？会不会出现"选了 A 就选不了更好的 B"？ |
| ④ | **反悔机制**：如果选错了能反悔吗？用什么维护"已选集合"？（堆） |
| ⑤ | **数据结构**：需要什么辅助结构？小根堆？大根堆？vector 维护单调？ |

### 关键判断逻辑

```
能不能排序？
├── 能 → 排序 + 遍历 + 堆（模板 A）  ← 80% 的贪心题
│   ├── 需要反悔？ → 模板 A（task.cpp）
│   └── 不需要反悔，每次贪最小/最大 → 模板 A 简化版（mergeapples.cpp）
└── 不需要排序（原顺序有意义） → 遍历 + 局部决策（模板 C）

有没有"替换历史"的需求？
├── 有 → 二分 + 替换（模板 B，LIS）
└── 无 → 直接贪
```

## 易错点

| 陷阱 | 对策 |
|---|---|
| 忘记用 `long long` | 合并代价、收益总和可能超过 `int`，有加法/乘法就用 `long long` |
| `priority_queue` 默认是**大根堆** | 小根堆要写 `greater<T>`，别写反 |
| 反悔时忘判 `!heap.empty()` | `heap.top()` 前必须判空 |
| 贪心策略虽然局部最优但**不保证全局最优** | 想一个反例——如果有反例，说明贪心不成立，要换 DP |
| 排序后丢失了原始顺序 | 有些题原始顺序有意义（如"相邻"约束），不要随便排序 |
