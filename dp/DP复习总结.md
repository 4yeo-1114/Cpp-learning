# DP 动态规划 —— 复习总结

> 覆盖 `dp/` 文件夹下全部 11 道题目，按类型分组讲解。每道题包含：题目描述、复杂度分析、状态定义、转移方程、关键边界、以及实现中容易踩的坑。最后给出 DP 通用解题模板和易错点清单，方便考前快速回顾。

## 一、题目分类总览

| 类别 | 题目 | 核心模式 |
|---|---|---|
| **线性 DP** | 爬楼梯、打家劫舍、最长递增子序列、乘积最大子数组 | `dp[i]` 只依赖前面固定个状态，通常一维 |
| **背包 DP** | 分割等和子集（0/1 背包）、零钱兑换 + 完全平方数（完全背包） | 选/不选物品，有容量约束 |
| **字符串 DP** | 单词拆分、最长有效括号 | 前缀/区间划分，下标运算 |
| **组合数学** | 杨辉三角 | 二维递推 |
| **非典型 DP** | 接雨水 | 前缀/后缀最值（也可用双指针/单调栈，不算严格 DP） |

### 1. 爬楼梯 (Climb Stairs) —— 「斐波那契」入门题

**题目回顾**：一次可以爬 1 阶或 2 阶，问爬到第 n 阶共有多少种不同的方法。

**复杂度分析**：

| 实现方式 | 时间复杂度 | 空间复杂度 |
|---|---|---|
| 暴力递归 | O(2^n) | O(n) 递归栈 |
| 记忆化搜索 | O(n) | O(n) |
| 自底向上递推 | O(n) | O(n) |
| 滚动变量优化 | O(n) | O(1) |

**核心思路**：

- **状态定义**：`dp[i]` = 爬到第 i 阶的方法总数。
- **转移方程**：`dp[i] = dp[i-1] + dp[i-2]`
  - 解释：要到达第 i 阶，最后一步可能是跨了 1 阶（从 i-1 过来），也可能是跨了 2 阶（从 i-2 过来）。两种选择的方法数加起来就是总方法数。
- **边界条件**：`dp[0] = dp[1] = 1`
  - 第 0 阶（地面）只有一种方法：站着不动。第 1 阶也只有一种：跨 1 阶上去。

**这道题在文件中展示了 DP 最完整的进化链**，也是学习 DP 最经典的路径：

```
暴力递归（指数级，会超时）
  → 记忆化搜索（加个 memo 数组，算过的直接返回）
    → 自底向上递推（用循环替代递归，常数更小）
      → 滚动变量（发现只依赖前两个状态，用两个变量就够了）
```

这个"**递归 → 记忆化 → 递推 → 空间优化**"的四步走，是 DP 最核心的思维方式。尤其是「记忆化搜索 → 递推」这一步：把递归翻转为循环，就是**自顶向下**到**自底向上**的转变，后面所有题目都遵循这个思想。

**补充：大数加法版**。当 n 非常大时（比如 n > 45），`int` / `long long` 都会溢出。文件中用 `vector<int>` 模拟高精度加法（个位在索引 0），本质和 DP 无关，但体现了**整数溢出是 P0 级问题**的意识——考试时如果题目没有给 mod，要想到是否需要高精度。

### 2. 打家劫舍 (House Robber) —— 「相邻不可选」约束

**题目回顾**：数组 `nums` 表示每家金额，不能偷相邻两家，求最大总金额。

**复杂度**：时间 O(n)，空间可优化到 O(1)。

**核心思路**：

- **状态定义**：`dp[i]` = 偷前 i 座房子能拿到的最大金额（i 从 0 开始编号）。
- **转移方程**：`dp[i] = max(dp[i-1], nums[i] + dp[i-2])`
  - **不偷第 i 家**：那就继承前 i-1 家的最优解 → `dp[i-1]`
  - **偷第 i 家**：那第 i-1 家绝对不能碰，只能加上前 i-2 家的最优解 → `nums[i] + dp[i-2]`
  - 两者取最大值，就是当前的最优决策。
- **边界条件**：
  - `n == 1` 直接返回 `nums[0]`（只有一个房子，直接偷），**必须提前判，否则后面 `dp[1]` 会越界**。
  - `dp[0] = nums[0]`：只有一家时偷这家。
  - `dp[1] = max(nums[0], nums[1])`：两家只能偷其中一家，取大的。

**🔗 与爬楼梯的相似性**：两道题都是 `dp[i]` 依赖 `dp[i-1]` 和 `dp[i-2]`，属于同一类线性递推。区别在于爬楼梯是把两种情况**加起来**（求总数），打家劫舍是**取 max**（求最优值）。这道题也比爬楼梯多了一步：第 i 个元素有"选还是不选"的决策，这是 DP「最优子结构」的典型体现。

### 3. 最长递增子序列 (LIS) —— 「以 i 结尾」的经典定义方式

**题目回顾**：给定无序数组，求最长严格递增子序列的**长度**（子序列不要求连续）。

**复杂度**：时间 O(n²)，空间 O(n)。进阶做法用贪心 + 二分可以做到 O(n log n)，文件中未涉及。

**核心思路**：

- **状态定义**：`dp[i]` = **以第 i 个元素结尾**的最长递增子序列的长度。
  - 这一定义方式是 LIS 的关键：不是"前 i 个元素中的 LIS 长度"，而是强制以 nums[i] 结尾。因为只有这样定义，我们才能通过比较 `nums[j]` 和 `nums[i]` 的大小来决定能不能把 nums[i] 接在某个序列后面。
- **转移方程**：遍历所有 j < i，如果 `nums[j] < nums[i]`（可以接在后面），则：
  ```
  dp[i] = max(dp[i], dp[j] + 1)
  ```
  初始时每个 `dp[i]` 至少为 1（只包含自己这一个元素）。
- **答案**：`max(dp[0..n-1])` —— 这里有一个经典坑！

> ⚠️ **易错点**：答案**不是** `dp[n-1]`！因为最长的递增子序列不一定以最后一个元素结尾。必须遍历整个 dp 数组取最大值。代码里的注释也特别强调了这一点。

**记忆化搜索版本**：文件中也给出了递归写法，结构完全对称——`dfs(i)` 返回以 i 结尾的 LIS 长度，递归内部枚举 j < i 并取 max，最后 `+1`（把自己算进去）。外部需要遍历所有 i 取 max。注意 memo 初始化为 0 是可行的，因为 LIS 长度至少为 1（不会是 0）。

### 4. 乘积最大子数组 (Max Product) —— 「负负得正」的精彩设计

**题目回顾**：求连续子数组的最大乘积（子数组必须连续，不同于 LIS 的子序列）。

**复杂度**：时间 O(n)，空间 O(1)。

**核心思路**：

为什么这道题不能像"最大子数组和"一样只维护一个 `imax`？因为**负数 × 负数 = 正数**。如果当前元素是负数，之前累积的最小乘积（一个绝对值很大的负数）乘以它，反而可能变成最大的正数。所以我们必须**同时维护当前的最大值 `imax` 和最小值 `imin`**。

- **当 `nums[i]` 是负数时**：先把 `imax` 和 `imin` 交换。因为乘上负数会让大小关系反转——原来的最大值变最小，最小值变最大。
- **计算新的 imax 和 imin**：每一步都有三种选择：
  1. **自己单干**：不管前面了，就从当前的 `nums[i]` 重新开始
  2. **和前面的 imax 连着乘**：`nums[i] * imax`
  3. **和前面的 imin 连着乘**：`nums[i] * imin`
  - `imax = max(nums[i], nums[i] * imax)`
  - `imin = min(nums[i], nums[i] * imin)`（注意这里用的是 swap 之前的 imin）
- **即时更新答案**：`ans = max(ans, imax)`

**手推一遍 `[-2, 3, -4]` 来感受**：

```
初始状态：imax = -2, imin = -2, ans = -2

遇到 3（正数）：
  不交换。
  imax = max(3, -2×3) = 3          ← 自己单干更好
  imin = min(3, -2×3) = -6         ← 保留了这个超小值，后面翻盘用
  ans  = max(-2, 3) = 3

遇到 -4（负数）：
  先交换！imax = -6, imin = 3
  imax = max(-4, -6×-4) = 24      ← 绝地翻盘！最小值×负数=最大正数
  imin = min(-4, 3×-4) = -12
  ans  = max(3, 24) = 24

最终答案 24 ✓
```

这道题在 DP 中属于"**状态需要冗余信息**"的典型代表——看起来只需要维护最大值，但为了应对负数的翻转效应，必须同时记录最小值。这种"多维护一个状态"的思想在 DP 中非常常见。

### 5. 分割等和子集 (Can Partition) —— 「0/1 背包」判定版

**题目回顾**：判断能否将数组分割成两个和相等的子集。

**复杂度**：时间 O(n·sum)，空间 O(sum)（一维优化后）。

**核心思路**：

这道题的关键在于**转化**。设数组总和为 S：

1. 如果 S 是奇数，不可能平分成两个整数和的子集 → 直接返回 `false`。
2. 如果 S 是偶数，问题变成：**能否从数组中选出若干个数，使它们的和恰好为 S/2？**

这就转化成了经典的 **0/1 背包问题（"能否恰好装满"版本）**。每个数是一件物品，价值等于重量，背包容量为 S/2，问能否恰好装满。

- **状态定义**：`dp[i][j]` = 能否从 `nums[0..i]` 中选出一个和恰好为 j 的子集（`i` 从 0 编号）。
- **转移方程**：对第 i 个数 `nums[i]`，有两种决策：
  - **不选**：问题变成从 `nums[0..i-1]` 中凑 j → `dp[i-1][j]`
  - **选**：问题变成从 `nums[0..i-1]` 中凑 `j-nums[i]` → `dp[i-1][j-nums[i]]`
  - 两者有一个成立即可：`dp[i][j] = dp[i-1][j] || dp[i-1][j-nums[i]]`
- **递归边界**：`dfs(-1, 0) = true`（没有数字可选时，凑出 0 是可行的），`dfs(-1, >0) = false`（凑不出任何正数和）。
- **递推边界**：因为递推的下标不能为负，采用 `f[i+1][j]` 表示"前 i 个数字"，则 `f[0][0] = true`。

**文件提供了三种实现方式**：

1. **记忆化搜索**（自顶向下）：递归函数 `dfs(i, j)`，用 `memo[i][j]` 记忆化，-1 表示未计算。
2. **二维递推**（自底向上）：`f[i+1][j]` 的二维数组，按 0/1 背包模板：外层遍历物品，内层遍历容量。
3. **一维空间优化**：`f[j] = f[j] || f[j-x]`，**j 必须从大到小倒序遍历**。

> ⚠️ **为什么一维时必须倒序？** 因为 `f[j-x]` 代表的是"上一层"（即前 i-1 个物品）的状态。如果正序遍历，`f[j-x]` 可能已经被当前这一层的更新覆盖了，相当于同一个物品被用了多次，这就退化成了完全背包。倒序遍历保证了当我们计算 `f[j]` 时，`f[j-x]` 还是上一层留下的旧值。

**额外优化**：文件中一维版本还做了一个剪枝——`s2 = min(s2 + x, sum/2)`，因为和不可能超过 sum/2，内层循环从 `s2` 开始倒序枚举即可，不用每次从 `sum/2` 开始，省了一些无用遍历。

### 6. 零钱兑换 (Coin Change) —— 「完全背包」标准模板

**题目回顾**：给定面额数组 `coins` 和目标金额 `amount`，求凑出 amount 所需的最少硬币数。每种硬币无限使用。

**复杂度**：时间 O(n·amount)，空间 O(amount)。

**核心思路**：

这道题和分割等和子集的核心区别在于：**每种硬币可以用无限次**。因此它是**完全背包**而非 0/1 背包。

- **状态定义**：`dp[j]` = 凑出金额 j 所需的最少硬币数。
- **转移方程**：`dp[j] = min(dp[j], dp[j - coin] + 1)`
  - 解释：要么不拿当前面额的硬币（沿用 `dp[j]`），要么拿一枚当前面额的硬币（`dp[j-coin] + 1`），取硬币数较少的那个。
- **边界条件**：`dp[0] = 0`（凑出 0 元需要 0 枚硬币）。
- **初始化技巧（重要！）**：因为是求**最小值**，dp 数组其余位置必须初始化为一个**极大的数**，比如 `amount + 1`（因为最坏情况全用 1 元硬币也只需要 amount 枚，amount+1 相当于无穷大）。如果初始化成 0，min 的结果永远都是 0，整个 DP 就废了。
- **遍历顺序**：外层遍历每种硬币，内层 j **从小到大正序**枚举。正序意味着 `dp[j-coin]` 可能是"已经拿过当前硬币"的状态，从而实现了无限次使用的效果。
- **返回值**：如果 `dp[amount] > amount`，说明凑不出来，返回 -1。

> **初始化技巧是 DP 中非常重要的一环**：求最大值时通常初始化为 0；求最小值时必须初始化为一个极大的数（无穷大），然后 `dp[0]` 单独设为基准值。这个规律在 coinChange 和 numSquares 中都适用。

### 7. 完全平方数 (Num Squares) —— 「完全背包」的同胞兄弟

**题目回顾**：求最少需要多少个完全平方数（1, 4, 9, 16...）的和等于 n。

**复杂度**：时间 O(n·√n)，空间 O(n)。

**核心思路**：

这道题和零钱兑换**几乎完全同构**。把"完全平方数"当作硬币面额（1, 4, 9, 16...），问题就变成了"用最少硬币凑出 n"。区别仅仅在于硬币面额不是输入给定的，而是由完全平方数生成的。

文件中提供了两种等价的思考角度：

- **视角 A（DP 直接定义）**：`f[i] = 1 + min(f[i - j²])`，其中 j² ≤ i。直接枚举最后一个完全平方数 j²，子问题是 `i - j²`。因为 `f[i - j²] < f[i]`，所以从小到大计算 i 即可。
- **视角 B（显式硬币数组 + 完全背包）**：先生成硬币数组 `coins = [1, 4, 9, 16...]`，然后套用和 coinChange 一模一样的完全背包模板。外层遍历物品（平方数），内层正序枚举金额。

> 🔗 **coinChange ≈ numSquare**，完全同构。吃透 coinChange 就能直接秒 numSquare。

### 8. 单词拆分 (Word Break) —— 「字符串上的 DP」

**题目回顾**：判断字符串 s 能否由 wordDict 中的单词拼接而成（单词可重复使用）。

**复杂度**：时间 O(n·max_len)（哈希查找 O(1)），空间 O(n)。

**核心思路**：

- **状态定义**：`dp[i]` = 字符串 s 的前 i 个字符（即 `s[0..i-1]`）能否被拆分成词典中的单词。
- **转移方程**：枚举 j < i，如果 `dp[j] == true`（前 j 个字符能被拆分）且 `s[j..i-1]` 出现在词典中，则 `dp[i] = true`。
- **边界条件**：`dp[0] = true`（空前缀视为可拆分）。
- **剪枝优化**：j 不需要从 0 开始枚举。找出词典中最长单词的长度 `max_len`，j 从 `max(i - max_len, 0)` 开始即可——因为比 max_len 还长的子串绝对不可能匹配词典中的任何单词。

**这道题和背包问题的关系**：虽然看起来像完全背包（单词可重复使用），但**循环顺序不能按"外层物品、内层容量"来写**。因为单词可以交替组合——比如 s = "ab"，词典 = ["a", "b"]，你可以先用 "a" 再用 "b"，而不是"用完某个单词就不再回头"。因此必须外层枚举 i（字符串前缀长度），内层枚举单词或 j（切分点）。文件里明确注释了这一点。

### 9. 最长有效括号 (LVP) —— 「下标运算型 DP」

**题目回顾**：给定一个只含 `'('` 和 `')'` 的字符串，找出最长有效括号子串的长度。

**复杂度**：时间 O(n)，空间 O(n)。

**核心思路**：

- **状态定义**：`dp[i]` = **以第 i 个字符结尾**的最长有效括号子串的长度。
- **关键观察**：有效子串不可能以 `'('` 结尾（因为左括号永远不能"闭合"），所以**只需要计算 `s[i] == ')'` 的位置**。

**两种情况**：

- **情况 A —— 隔壁就是对象 `...()`**：
  ```
  如果 s[i-1] == '('，则 dp[i] = dp[i-2] + 2
  ```
  `s[i-1]` 和 `s[i]` 直接配成一对 `()`，加上这对之前的有效长度 `dp[i-2]`。

- **情况 B —— 嵌套结构 `((...))`**：
  ```
  如果 s[i-1] == ')' 且 s[i - dp[i-1] - 1] == '('，则
  dp[i] = dp[i-1] + dp[i - dp[i-1] - 2] + 2
  ```
  解释：
  - `dp[i-1]` 是紧挨着 i 的那段有效子串长度
  - `s[i - dp[i-1] - 1]` 是跳过这段有效子串后，左边第一个字符。如果它是 `'('`，就和 `s[i]` 配对
  - `dp[i - dp[i-1] - 2]` 是这对括号左边的有效子串长度
  - `+ 2` 是这对括号本身

  所有的 `dp` 下标访问前都必须判断 `>= 0`，防止数组越界。

**答案**：`max(dp[0..n-1])`，因为最长有效子串不一定以最后一个字符结尾。

**栈解法补充**：文件中还提供了用栈的方法——初始化栈中放 -1 作为"断点"，遇到 `'('` 压入下标，遇到 `')'` 弹栈。如果弹完栈空了，把当前下标作为新的断点压入；如果栈不空，用 `i - stk.top()` 更新最大长度。两种方法都值得掌握。

### 10. 杨辉三角 (Pascal's Triangle) —— 「二维递推 / 组合数」

**题目回顾**：生成杨辉三角的前 numRows 行。

**复杂度**：时间 O(n²)，空间 O(n²)。

**核心思路**：

- **转移方程**：`ans[i][j] = ans[i-1][j-1] + ans[i-1][j]`
  - 每行首尾为 1，中间每个数等于它"左上方 + 右上方"两个数之和。
- **本质**：组合数恒等式 `C(n, k) = C(n-1, k-1) + C(n-1, k)`，即考虑某个特定物品"选或不选"——选则从剩下 n-1 个中选 k-1 个，不选则从剩下 n-1 个中选 k 个。

> 🐛 **已知 Bug**：文件中内层循环写的是 `for(int j=1; j<i; i++)`，循环变量递增写成了 `i++` 而不是 `j++`，会导致死循环。这是典型的"复制粘贴后忘了改变量名"错误，考试时一定要注意。

### 11. 接雨水 (Trapping Rain Water) —— 「前缀/后缀最值」

> 这道题严格来说不算 DP，但它的解法用到了"前缀最优值"的思想，放在 dp 文件夹里可以理解。建议和 DP 区分对待，把它当作前缀/后缀数组 + 双指针的题目。

**题目回顾**：给定柱状图高度数组，计算下雨后能接多少雨水。

**复杂度**：时间 O(n)，空间 O(1)（双指针优化版）。

**三种解法**：

- **方法一（前缀后缀数组）**：预处理 `leftMax[i]`（i 左边最高的柱子）和 `rightMax[i]`（i 右边最高的柱子），那么位置 i 能接的水量 = `min(leftMax[i], rightMax[i]) - height[i]`。如果这个值为负（当前柱子比两边都高），则接不到水，贡献为 0。时间 O(n)，空间 O(n)。

- **方法二（双指针优化）**：方法一需要两个额外的数组，但我们可以在双指针相向移动的过程中**动态维护**前缀最大值 `pre` 和后缀最大值 `suf`。哪边的最大值更小，就说明那一侧的"短板"确定了，可以安心地计算该侧指针位置的水量，然后移动那个指针。这样就把空间优化到了 O(1)。

- **方法三（单调栈）**：维护一个单调递减栈，栈中存下标。当遇到一个比栈顶高的柱子时，说明形成了一个凹槽：栈顶是凹槽底部，新柱子是右边界，栈中第二个元素是左边界。横向按层计算积水量。这种做法的思路和前面两种完全不同——前面是"竖着"算（每个位置上方有多少水），单调栈是"横着"算（每个高度的水层有多宽）。

## 四、DP 通用解题五步法

无论遇到什么 DP 题，按这五步来走，思路就不会乱：

```
① 状态定义 —— dp[i] 或 dp[i][j] 代表什么含义？
    ├── 一维：dp[i] = "前 i 个..." 或 "以 i 结尾..."
    └── 二维：dp[i][j] = "前 i 个物品，容量/目标为 j 时..."

② 状态转移方程 —— dp[i] 如何从更小的子问题推导？
    核心操作：对"第 i 个元素"做决策 —— 选 or 不选？接在后面 or 自己单干？
    这一步决定了遍历顺序（正序还是倒序）和依赖关系。

③ 边界条件 —— dp[0]、dp[1] 这些基准值是什么？
    dp[0] 往往是"空状态"（空数组、空字符串、和为 0），要给一个合理值。

④ 遍历顺序 —— 正序还是倒序？
    ├── 0/1 背包 → 容量倒序（防止同一物品被多次使用）
    ├── 完全背包 → 容量正序（允许同一物品被多次使用）
    └── 线性 DP → 通常正序（后面的依赖前面）

⑤ 答案位置 —— 返回什么？
    ├── dp[n-1] / dp[n]
    └── max(dp[0..n-1])（子序列类问题！）
```

## 五、三大 DP 模板（背下来直接用）

### 模板 1：线性递推（爬楼梯 / 打家劫舍）

```cpp
// 适用于：dp[i] 只依赖前 1~2 个状态
dp[0] = base0;
dp[1] = base1;
for (int i = 2; i <= n; i++) {
    dp[i] = f(dp[i-1], dp[i-2]);   // f 可以是 + 或 max 或 min
}
return dp[n];

// 空间优化版：两个变量滚动
int f0 = base0, f1 = base1, new_f;
for (int i = 2; i <= n; i++) {
    new_f = f(f1, f0);
    f0 = f1;
    f1 = new_f;
}
return f1;
```

### 模板 2：0/1 背包（分割等和子集 —— 每个物品最多用一次）

```cpp
// 可行性版本（能否恰好装满）
vector<bool> dp(target + 1, false);
dp[0] = true;
for (int x : nums) {
    for (int j = target; j >= x; j--) {   // ← 倒序是关键！
        dp[j] = dp[j] || dp[j - x];
    }
}
return dp[target];
```

### 模板 3：完全背包（零钱兑换 / 完全平方数 —— 每个物品无限次使用）

```cpp
// 求最小值版本
vector<int> dp(target + 1, INF);  // INF = amount+1 或 INT_MAX/2
dp[0] = 0;
for (int coin : coins) {
    for (int j = coin; j <= target; j++) {  // ← 正序是关键！
        dp[j] = min(dp[j], dp[j - coin] + 1);
    }
}
return dp[target] > target ? -1 : dp[target];

// 求方案数版本（如爬楼梯变体：一次可以跨 coins 中的步数）
vector<int> dp(target + 1, 0);
dp[0] = 1;
for (int j = 1; j <= target; j++) {        // ← 注意：求排列数时外层是容量！
    for (int coin : coins) {
        if (j >= coin) dp[j] += dp[j - coin];
    }
}
return dp[target];
```

## 六、初始化技巧 —— 最容易出错的地方

| 要求什么 | 初始化为 | 基准 dp[0] | 典型题目 |
|---|---|---|---|
| **最小值** | `INT_MAX` 或 `amount+1`（相当于 ∞） | 0 | coinChange, numSquares |
| **最大值** | 0（或 -1 标记不可达） | 视情况 | rob, lengthOfLIS |
| **可行性 (bool)** | false | true | canPartition, wordBreak |
| **方案数** | 0 | 1（"什么都不选"算一种方案） | climbStairs |

**核心原则**：求最小值初始化成 ∞，求最大值初始化成 0/-1，方案数初始化成 0，bool 初始化成 false。`dp[0]` 永远是基准情况，单独设置。

## 七、遍历顺序速查 —— 背包问题的灵魂

| 背包类型 | 外层循环 | 内层循环 | 内层方向 | 为什么 |
|---|---|---|---|---|
| **0/1 背包** | 物品 | 容量 | **倒序 ↓** | `f[j-x]` 必须是上一层的旧值，不能是本轮刚更新的 |
| **完全背包** | 物品 | 容量 | **正序 ↑** | `f[j-x]` 可以是本轮已更新的值，允许重复拿 |
| **求组合数** | 物品 | 容量 | 正序 | 物品顺序固定，不考虑排列 |
| **求排列数** | 容量 | 物品 | 正序 | 顺序不同算不同方案 |

**记忆口诀**："0/1 倒着走，完全正着走；组合先物品，排列先容量。"

## 八、空间优化通用思路

> **当前状态只依赖上一层 → 滚动数组（一维替代二维）；只依赖前几个 → 滚动变量（几个变量替代数组）。**

具体对应关系：

| 依赖关系 | 优化方式 | 题目举例 |
|---|---|---|
| `dp[i]` 只依赖 `dp[i-1]` 和 `dp[i-2]` | 两个变量 `f0, f1` 滚动 | climbStairs, rob |
| 二维 DP 只依赖上一行 | 一维数组 + 倒序（0/1 背包） | canPartition |
| 二维 DP 只依赖上一行（完全背包） | 一维数组 + 正序 | coinChange, numSquares |
| 二维 DP 依赖左边和上边 | 一维数组 + 正序 | yanhui 可优化 |

## 九、关键易错点清单（考前必看）

| # | 易错点 | 后果 | 涉及题目 |
|---|---|---|---|
| 1 | LIS/LVP 返回 `dp[n-1]` 而不是 `max(dp)` | 答案错误，因为最长子序列不一定以最后一个元素结尾 | LIS, LVP |
| 2 | 0/1 背包 j **正序**遍历 | 变成完全背包，同一个物品被多次使用 | canPartition |
| 3 | 求最小值时 dp 初始化为 0 | min 永远返回 0，DP 完全失效 | coinChange, numSquares |
| 4 | 乘积最大只维护 imax 不维护 imin | 负数翻转时丢失正确答案 | maxProduct |
| 5 | 访问 `dp[i-2]` 未判断 `i >= 2` | 数组下标越界 | climbStairs, rob, LVP |
| 6 | 背包问题未预先判断总和奇偶 / 目标范围 | 做了无用计算，或数组越界 | canPartition |
| 7 | 杨辉三角循环变量写错 (`i++` vs `j++`) | 死循环 | yanhui |
| 8 | 单词拆分按完全背包"先物品后容量"写 | 逻辑错误，单词组合顺序被限定 | wordBreak |

## 十、从这些题目中提炼的 DP 核心思想

1. **最优子结构**：大问题的最优解可以通过子问题的最优解推导出来。这是 DP 成立的前提。
2. **无后效性**：当前状态一旦确定，就不受"未来决策"或"如何到达当前状态"的影响。
3. **重叠子问题**：不同的递归路径会访问同一个子问题，所以需要记忆化 / 递推来避免重复计算。这也是 DP 区别于分治的关键——分治的子问题通常不重叠。
4. **状态定义比转移方程更重要**：定义清楚了，转移往往自然而然；定义模糊了，转移怎么写都别扭。
5. **"选还是不选"是最常见的转移模式**：从 0/1 背包到 LIS（选不选当前元素），从 rob（偷不偷当前房子）到 wordBreak（切不切当前单词），本质都是"对第 i 个元素做二元决策"。
6. **初始化决定成败**：最小值配 ∞，最大值配 0，方案数配 0 且 dp[0]=1。初始化错了后面全白算。
